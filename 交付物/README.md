## §2 证据分级（**最重要的一节，不许省**）

不是所有「证据」都值钱。**混级 = 制造新的失实**。每份证据必须标清它属于哪一级：

| 级别 | 含义 | 可信度 | 审查员可否据此宣布通过 |
|---|---|---|---|
| **L1 原始输出** | 当时粘贴的 stdout / stderr 原文，未删改未重排 | 高 | 可作技术证据 |
| **L2 事后重建** | commit 之后用 `git show` / `git ls-remote` 等**可重放**命令重建的事实 | 中 | 可作 git 层证据，**不可**当作运行时证据 |
| **L3 事后转述** | 从会话记录 / 记忆中摘出的输出片段（我原样搬，但当时是否完整已不可查） | 低 | 仅供参考，**须标明** |
| **L4 未留存** | 当时没留，现在补不出来 | 无 | **必须显式声明「未留存」，不许补写** |

### 硬规则

1. **L4 一律写「未留存」，绝不补写一个「大概是这个」的输出。** 补写输出 = 伪造证据，比没证据更糟。
2. **L3 必须标出**。L3 冒充 L1 是最容易被自己骗过去的一种失实。
3. **页面级证据永远为 0**。我没有浏览器 —— 任何 `交付物/*.md` 里都不会有页面截图，因为那意味着伪造。页面级一律写「归星轨 Playwright + Edge」。
4. **静态证据 ≠ 运行时证据**（AGENTS.md 红线 2）。在运行 bundle 里 grep 到 `key`，**不等于** React 真的重挂载了。这类天花板必须写在文件里。

## §3 命名

```
交付物/运行时证据-<短sha>.md          # 每笔 commit 一份
交付物/未覆盖声明-<主题>-<短sha>（<日期>）.md
```

- 短 sha = 7 位。
- 日期用 `YYYY-MM-DD`。

---

## §4 审查员怎么用

每份文件开头都有 **§元信息**（sha / 时间 / 双端 SHA / 改了什么 / 跑了什么 / 未覆盖声明 / 待谁验收）。

审查员可以直接：
- 核 `git show --stat <sha>` 对「改了什么」的文件行数
- 核 `git ls-remote` 对双端 SHA
- 对照「未覆盖声明」确认页面级判据是否仍待执行
- **对 L2/L3 条目自行降级处理**，不必采信我的措辞

## §6 收工流程接入点

WAKEUP.md「收工后必须做的事」链序为 **落盘 → 固化 → 核 → 推**。本目录属「固化」环节：

- 在 commit 之前写（原始输出必须当时留，事后无法重建）
- 与代码同一笔 commit 入仓，或紧随其后一笔 `docs(证据)` 入仓
- **不入 `ledger_check` 的备份范围**（`backup.sh` 同步清单是 WAKEUP.md 定的白名单，本目录未列入 —— 要列入需星云点头）
