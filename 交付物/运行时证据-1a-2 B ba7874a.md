## §2 🔴 A 笔的真缺陷（B 笔实测抓出）—— **L1**

**现象**：建表能过（约束只是被定义），但**任何 text / table 块写入都失败**：

```
sqlite3.IntegrityError: CHECK constraint failed: ck_content_blocks_text_shape
```

**根因定位过程**（不是猜，是逐层排除）：

```
① 裸 SQL 手工 INSERT text 块（text_content 有值、table_json 显式 NULL）→ 成功
   ⇒ CHECK 表达式本身没错
② ORM 单插入（不显式赋 None）→ 成功
③ ORM 显式赋 None（router 的写法）→ 失败
   ⇒ 问题在「ORM 显式赋 None」的路径
④ 查 SQLAlchemy 语义：JSON 列默认 none_as_null=False
   ⇒ Python 的 None 被序列化成 **JSON 字面量 null**，不是 SQL NULL
   ⇒ CHECK 判据 table_json IS NULL 恒为 false
```

**PG 侧同理**（JSONB 也是 JSON 语义，`IS NULL` 对 JSON `null` 为 false）⇒
**这不是 SQLite 特有**，是跨库的语义矛盾。

**修法**：JSON 列加 `none_as_null=True` ⇒ None 落成真正的 SQL NULL。实测：

```
none_as_null=True → typeof(j)= null  IS NULL= 1
```

**模型与迁移同步改**（`academic.py` + `0013`）—— `none_as_null` 是**客户端绑定
行为，不改 DDL** ⇒ 已应用的 dev/test 库**无需重跑**，实测无漂移：

```
dev 库 content_blocks:      meta|jsonb   table_json|jsonb
从零重建（改后迁移文件）:   meta|jsonb   table_json|jsonb
```

**为什么单独成笔、不 amend `e736e17`**：该笔**已推 origin + github** ⇒ amend
需 force-push 改写已推历史。故单独一笔 fix，message 里写明修的是哪一笔。

## §3 🔴 删组用 bulk delete 而非 db.delete —— **L1**

**现象**：删组时崩在

```
sqlalchemy.exc.IntegrityError: (sqlite3.IntegrityError) CHECK constraint failed: ck_question_images_owner_not_null
[SQL: UPDATE question_images SET group_id=? WHERE question_images.id = ?]
[parameters: (None, 1)]
```

**根因**（两条合起来）：

1. `QuestionImage` 有**两个**父关系（`question` / `group`），而 `Question.images`
   侧是 `delete-orphan` ⇒ 父删时 ORM 会先把子行的 `group_id` 置 NULL（想置空再删）
2. XOR CHECK 要求 `question_id` / `group_id` **恰好一个**非空 ⇒
   `UPDATE group_id=NULL` 直接撞约束

**为什么 `passive_deletes=True` 救不了**：

```
QuestionGroup.images   cascade=merge,save-update  passive_deletes=True  lazy=selectin
```

`passive_deletes=True` 只在「ORM 不加载子集合」时生效，而 `lazy="selectin"`
⇒ 集合**已被加载** ⇒ ORM 仍做 de-associate。

**修法**：**bulk delete**（`db.execute(delete(QuestionGroup).where(...))`）彻底
绕开 ORM 级联，只删组一行，DB 的 `ON DELETE CASCADE` 按 FK 定义带走三张子表。
产物语义与 `db.delete(group)` 相同（组没了、子行全没了），且**零子行 UPDATE**。

> 先试过 `db.expunge(child)` 分离子行 —— 也能过，但留 SAWarning
> 「delete operation along 'QuestionGroup.images' will not proceed」⇒ 换成
> bulk delete，警告消失，且语义更直白。
