## §2 门禁（本轮返工的第二件）

### 2.1 旧版（`03843de`）**确实**有两个真缺口 —— **L1（核源）**

**缺口 ①：读的是**容器副本**，不是仓库工作树。**

```
$ grep -n "alembic" docker-compose.yml
76:    # 启动链：先 alembic upgrade head（建表），再 exec uvicorn。
79:    command: ["sh", "-c", "alembic upgrade head && exec uvicorn app.main:app --host 0.0.0.0 --port 8000"]

$ docker inspect thp-backend --format '{{range .Mounts}}{{.Type}} {{.Source}} -> {{.Destination}}{{"\n"}}{{end}}'
bind /home/wsq_1/tiered-homework-platform/data/uploads -> /app/data/uploads
```

⇒ **只有 `data/uploads` 是 bind mount**，`/app/alembic` 是**镜像里烤进去的副本**
（inode 不同：仓库 `233209` vs 容器 `233212`）。

⇒ 旧版用 `docker exec thp-backend alembic heads` 取期望值 = **读容器副本**。
⇒ **仓库加了迁移但没重建容器时，门禁看不见** ⇒ 门禁失守。

**缺口 ②：`alembic heads | tail -1` 只取最后一个 head。**
分叉成 2 个 head 时会**静默取一个**，不报错。

### 2.2 改法 —— 新增 `scripts/alembic_head.py`

**不依赖 alembic 运行环境**，直接静态解析**仓库工作树**的
`backend/alembic/versions/*.py` 的 `revision` / `down_revision` 建图求 head。

用 `ast`（不是正则）—— 因为本仓库两种写法都有：

```
$ grep -h "^revision" backend/alembic/versions/*.py
revision = "0001_initial"                          ← ast.Assign（0001）
revision: str = "0002_academic_models"             ← ast.AnnAssign（0002+ 全用这个）
```

⚠️ **我第一版解析器只认 `ast.Assign`** ⇒ 在 `0002` 上直接失败
（`解析失败: 0002_academic_models.py: 找不到 revision 赋值`）⇒ 已修（两种都认）。

**退出码约定**：`0` = 恰好 1 个 head ｜ `2` = 无 head（空/有环）｜ `3` = 分叉 ｜ `4` = 解析失败。

**四种情形实测 —— L1**：

```

0013_groups_and_blocks
exit=0

$ python3 scripts/alembic_head.py /tmp/ah_fork        # 造 2 个 head

exit=3

$ python3 scripts/alembic_head.py /tmp/ah_bad         # down_revision 非字面量
解析失败: 9003_bad.py: down_revision 不是字面量，无法静态解析

$ python3 scripts/alembic_head.py /tmp/ah_empty

```

**门禁第 11 项改写**（`scripts/ledger_check.sh`）：

- 期望值 = `python3 scripts/alembic_head.py`（**仓库工作树**）
- 实测值 = `alembic current`（dev 库真值，不变）
- 新增 **head 唯一性**分支（`rc=3` ⇒ ❌「revision 图**分叉**」）
- 修法提示从「只 upgrade head」改成「**先重建镜像**再 upgrade head」
  （因为容器副本才是真凶）

### 2.3 ⭐ 反向实测：**人为制造落后必须 ❌** —— **L1**

星轨点名要的：「**贴一条「人为制造落后必须 ❌」的实测，不改出这条就等于没验**」。

**做法**：在**仓库工作树** `backend/alembic/versions/` 放一笔假迁移
（`revision=0014_zz_fake_probe`, `down_revision=0013_groups_and_blocks`），
让仓库 head 跑到 0014 而 dev 库还在 0013。

**为什么这个做法安全**（已核源）：容器 `/app/alembic` 是镜像副本、**不是 mount**
⇒ 假迁移**不会**被容器的 `alembic upgrade head` 捡到 ⇒ **dev 库绝对安全**，
且假文件删掉即完全回退（无需 `downgrade`、无需改库）。
