## 9. 教训沉淀（D-43-X / D-38 候选）

### 9.1 D-43-X 候选规则（3 条新增 + 1 条来源）

#### D-43-X-1（新增）：执行 git mv / git rm / rebase 前先验证跟踪状态
> **执行 `git mv` / `git rm` / `git pull --rebase` / rm-then-add 前，先 `git ls-files <target>` 验跟踪状态**。
> 未跟踪 → 不要 git mv；要么先 `git add`，要么 plain mv + git add。
> 1 行命令成本 = 杜绝一次 N-3 这种 spec 偏离。

**证据**：本次 N-3 `git mv` 直接报错才发现 plans/ untracked。本来 1 行 `git ls-files plans/` 就能提前发现。

**来源**：N-3 subagent `memory/2026-09-23.md` §5.1。

#### D-43-X-2（新增）：决策室产出文档 ≠ 决策室已 git add
> **决策室产出新文档后，由下一个 subagent 在首次接触时做「git add + git ls-files 双向核对」并把核对结果回执**。

**证据**：`plans/README.md` 明文要求 plans/ 必须 tracked，但写完当天没 add。说明决策室产出文档 ≠ 落地仓库状态 — 与 D-39/D-41「落字未落地」同构（D-42 第 4 层）。

**来源**：N-3 subagent `memory/2026-09-23.md` §5.2。

#### D-43-X-3（新增）：CI 验证优先用 GitHub Actions API
> **CI 验证优先用 `gh api` 或 `curl` 直接打 GitHub Actions API**，不受 readability 裁剪 / 第三方 badge 服务限制。
> 备选：本地起 gh CLI（需要 `gh auth login`）。

**证据**：N-1 subagent 三次尝试拉 step badge 都受阻（API rate limit + readability 裁剪 + 无 gh CLI）。

**来源**：本会话 N-1 报告。

#### D-43-X-4（来源 9/22 反思 + 9/23 验证）：每轮收工 1 行 grep 表
> **每轮收工检查上一轮新落字规则的执行次数；次数为 0 = 标 ⚠️ 并列入下轮必办**。

**证据**：
