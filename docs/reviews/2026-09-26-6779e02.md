### 2.4 ci.yml B1 重写真 wait-postgres（commit `6779e02`）

**位置**：`.github/workflows/ci.yml` line 100-129

**当前 HEAD ci.yml 关键 step**：

```yaml
- id: wait-postgres
  name: Wait for postgres ready (fail-fast)
  run: |
    set -e
    echo "=== DATABASE_URL: ${DATABASE_URL} ==="
    echo "=== Probing postgres:5432 ==="
    for i in $(seq 1 30); do
      # Probe 1: DNS resolution (Python socket.getaddrinfo)
      if python3 -c "import socket; socket.getaddrinfo('postgres', 5432)" 2>/dev/null; then
        # Probe 2: TCP connect (bash /dev/tcp)
        if (timeout 5 bash -c "echo > /dev/tcp/postgres/5432") 2>/dev/null; then
          # Probe 3: psycopg connect (real PG handshake)
          if python3 -c "import psycopg; conn = psycopg.connect('${DATABASE_URL}', connect_timeout=5); conn.close()" 2>/dev/null; then
            echo "postgres ready after ${i} attempts"
            exit 0
          fi
        fi
      fi
      echo "attempt $i failed, retrying..."
      sleep 2
    done
    echo "ERROR: postgres not reachable after 60s (60 attempts)"
    echo "=== Diagnostic dump ==="
    echo "--- /etc/hosts ---"
    cat /etc/hosts 2>&1
    echo "--- getent hosts postgres ---"
    getent hosts postgres 2>&1 || echo "FAIL getent"
    echo "--- ps aux postgres ---"
    ps auxf 2>&1 | grep -i postgres | head -5 || echo "no postgres process"
    exit 1
```

**审查内容**：

a) **三层 probe 实现**：
- Probe 1 (DNS)：`python3 -c "import socket; socket.getaddrinfo('postgres', 5432)"` — Python 内置 socket 模块，无额外依赖 ✓
- Probe 2 (TCP)：`(timeout 5 bash -c "echo > /dev/tcp/postgres/5432")` — bash 内置 /dev/tcp，无 nc 依赖 ✓
- Probe 3 (PG handshake)：`python3 -c "import psycopg; conn = psycopg.connect('${DATABASE_URL}', connect_timeout=5); conn.close()"` — psycopg 已是 Python 项目依赖，不算额外依赖 ✓

b) **Fail-fast 设计**：
- `set -e` (line 103) — bash 错误立即退出 ✓
- 嵌套 if 三层：必须三层全部成功才 `exit 0`；任一层失败 → 跳过 `exit 0` → 进入 retry ✓
- `exit 1` (line 129) — 30 次重试全部失败时明确退出码 1 ✓

c) **超时控制**：
- 30 attempts × 2s sleep = 60s 总超时 ✓
- 每次 probe 内有 5s timeout（timeout 5 + connect_timeout=5）✓
- 总计 ~30 × (5s + 5s + 5s + 2s) = 510s 上限 = 不合理！

**P1 观察（不影响本审查通过）：**
- 每次 probe 内部 timeout = 5s（bash timeout 5）+ 5s（psycopg connect_timeout）= 单次 ~10s 上限
- 30 次循环 × ~10s = 上限 ~300s = 5 分钟
- 但 sleep 2s 在循环末尾 + 总上限 ~300-510s
- **实际场景**：DNS 解析失败时 Probe 1 立即返回（毫秒级），不会触发 Probe 2/3 的 timeout → 单次循环 ~2s
- 只有在 DNS 通过但 TCP 阻塞时才会触发 5s timeout（Probe 2）= 30 × 5s = 150s 上限
- **真实失败场景下**（参考 run #16/#19 实证 DNS 不可达）：DNS probe 立即 fail → 30 × 2s = 60s 退出 ✓
- **结论**：超时设计与实证失败模式匹配（DNS 失败时 ~60s 退出，符合设计意图）

d) **诊断 dump（line 121-128）**：
- /etc/hosts、getent hosts postgres、ps aux postgres = 三源诊断 ✓
- 用于"postgres not reachable after 60s"失败时的根因排查
- 与 5ce4644 的 debug-postgres 诊断 dump 设计一致，但**这次是真的 wait 步 + fail-fast，不是纯 dump-and-exit-0 的伪装 step**

e) **不依赖额外二进制**：
- 注释明写"不依赖 pg_isready / psycopg / nc 二进制（避免额外依赖）"
- 实际代码只用：Python 内置（socket）+ bash 内置（/dev/tcp）+ Python 项目依赖（psycopg）+ coreutils（cat、ps、grep、getent）
- ps 在某些 minimal 镜像可能缺失（ubuntu-latest ✓）
- getent 在某些 minimal 镜像可能缺失（ubuntu-latest ✓）
