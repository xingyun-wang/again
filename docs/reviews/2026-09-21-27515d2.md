**替代证据（独立 SQLAlchemy 2.0 minimal，复现修复模式）**：

```bash
$ cd /home/wsq_1/tiered-homework-platform/backend
$ python3 -c "
from sqlalchemy import create_engine, Column, Integer, ForeignKey, event
from sqlalchemy.orm import declarative_base, sessionmaker
from sqlalchemy.pool import StaticPool
Base = declarative_base()
class Parent(Base):
    __tablename__ = 'parent'
    id = Column(Integer, primary_key=True)
class Child(Base):
    __tablename__ = 'child'
    id = Column(Integer, primary_key=True)
    parent_id = Column(Integer, ForeignKey('parent.id'), nullable=False)
engine = create_engine('sqlite:///:memory:', connect_args={'check_same_thread': False}, poolclass=StaticPool, future=True)
@event.listens_for(engine, 'connect')
def _fk(dbapi_conn, _conn_record):
    cur = dbapi_conn.cursor(); cur.execute('PRAGMA foreign_keys=ON'); cur.close()
Base.metadata.create_all(engine)
SessionLocal = sessionmaker(bind=engine, autoflush=False, autocommit=False, expire_on_commit=False)
s = SessionLocal()
p = Parent(); s.add(p); s.flush()
print(f'After flush: p.id = {p.id}')
c = Child(parent_id=p.id); s.add(c); s.flush()
print(f'After flush: c.id = {c.id}, c.parent_id = {c.parent_id}')
s.commit()
print('COMMIT OK')
"
After flush: p.id = 1
After flush: c.id = 1, c.parent_id = 1
COMMIT OK
```

**复现解读**：
- ✅ `Parent` + `Child`（FK）能 commit
- ✅ `s.add(p); s.flush()` → `p.id = 1`（**修复模式**：循环内每个 chapter 单独 flush 拿 ID）
- ✅ `Child(parent_id=p.id)` → `c.parent_id = 1`（非 None）
- ✅ `s.commit()` → COMMIT OK（无 FK NOT NULL violation）

这独立证明 P1-1-1 修复的 `db.flush()` 模式（autoflush=False + FK enforcement + flush 后拿 ID 再创建 child row）逻辑成立。
