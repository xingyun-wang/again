## 决策详情

### D-10：AI 辅助录入边界（重要）

**问题**：v0.5 §5.3.5 引入「AI 辅助录入」——LLM 预提取 PDF 里的标题 / 关键概念 / 重点 / 难点，星云审阅 + 编辑。

**三种 AI 能力的边界**：
- **内容生成**（AI 出题 = **禁**）：v0.4 / v0.5 §3.3 强拍板
- **综合分析**（AI 备课 = **允许**）：v0.5 §5.1-5.4 范围内
- **数据提取**（AI 辅助录入 = **允许，人在回路**）：v0.5 §5.3.5 新能力

**为什么"数据提取"不违反"内容生成禁令"**：
- AI 提取的是 PDF 里**已有**的内容（教参 / 教师手册）
- 星云审阅 + 编辑后入库
- 等价于"AI 辅助 OCR + 排版"，不是"AI 生成新题目"

**未来警惕**：AI 辅助录入如果演化为"AI 直接入库 + 老师只看"，会滑向内容生成。每次升级 AI 辅助录入前要重新评估。

### D-21：v0.5 §9 技术选型定稿（载曜做判断）

**问题**：§9 技术性问题，星云没有辨识能力，明确授权载曜做判断。**关键约束：「不能阻碍前路」**（产品未来面向大区域 / 全学段 / 全学科）

**5 拍板**（3 个偏离原默认假设）：
1. **Q1 前端** = A React 18 + TS + Vite + Ant Design 5（沿用 v0.4）
2. **Q2 后端** = **A** Python 3.11 + FastAPI + **Celery**（偏离默认 B「去 Celery」；Celery 依赖保留，MVP 不同步启用）
3. **Q3 数据库** = **C** **全程 PG**（偏离默认 B「MVP 全 SQLite」；Docker Compose 简化部署）
4. **Q4 LLM** = **DeepSeek-V3 + Provider 抽象层**（偏离默认 A「DeepSeek 单选」；MVP 用 DeepSeek，架构层抽象 Provider，未来可切）
5. **Q5 部署** = **Docker Compose 单机 MVP + 无状态 FastAPI**（沿用默认 C 改良；无状态 = 横向扩展零成本）

**3 个偏离默认的取舍**：
- **Q2 保留 Celery**：大区域 / 全学科意味着分布式任务队列是扩展关键，MVP 阶段不用但保留依赖，零重构
- **Q3 直接全程 PG**：SQLite 在大区域 / 全学段 / 全学科扛不住（数据量大 + 多实例并发 + 跨表关联）；Docker Compose 简化部署
- **Q4 加 Provider 抽象层**：当前用 DeepSeek，但架构上可切 GPT-4o / Claude / 国产模型；Phase 2 多区域时按区域选 Provider

**关键架构决策（避免未来重构）**：
- 无状态 FastAPI（横向扩展零成本）
- LLM Provider 抽象（多模型切换零重构）
- 数据模型预留学段 / 学科字段（v0.5 §1 已锁）
- Celery 依赖保留（分布式任务队列预留）
- OSS 对象存储抽象（MVP 本地文件夹实现）

**CHARTER §7.0 触发**：§9 拍板后，写新工程要在 subagent 工地，不在决策室。
