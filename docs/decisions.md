## 决策详情

### D-10：AI 辅助录入边界（重要）

**问题**：v0.5 §5.3.5 引入「AI 辅助录入」——LLM 预提取 PDF 里的标题 / 关键概念 / 重点 / 难点，星云审阅 + 编辑。

**三种 AI 能力的边界**：
- **内容生成**（AI 出题 = **禁**）：v0.4 / v0.5 §3.3 强拍板
- **综合分析**（AI 备课 = **允许**）：v0.5 §5.1-5.4 范围内
- **数据提取**（AI 辅助录入 = **允许，人在回路**）：v0.5 §5.3.5 新能力

**为什么"数据提取"不违反"内容生成禁令"**：
- AI 提取的是 PDF 里**已有**的内容（教参 / 教师手册）
- 星云审阅 + 编辑后入库
- 等价于"AI 辅助 OCR + 排版"，不是"AI 生成新题目"

**未来警惕**：AI 辅助录入如果演化为"AI 直接入库 + 老师只看"，会滑向内容生成。每次升级 AI 辅助录入前要重新评估。

### D-32：P0/P1/P2 判级标准（2026-09-20）

**问题**：审查员与作者对"什么算 P0"会扯皮；标准必须事先定死、不能事后改。

**拍板** —— P0 命中任一即为 P0：
1. **数据可信性**：写库内容与来源不符；对外结论（统计/验收/报表）可能失真
2. **不可逆损失**：删除原件 / 无备份覆盖写 / 迁移不可回滚
3. **安全与归属边界失效**：越权读写 / ID 存在性泄漏
4. **门槛 fail-open**：最坏实现（mock / fallback / 空壳）可让门槛亮绿
5. **单点可用性**：单个正常请求可导致服务不可用（无上限入内存 / OOM）

**P1**：不影响当前正确性，但在既定路线上造成返工或阻塞。
**P2**：整洁度、文档、命名、死代码。

**附加纪律**：
- 无法用一条命令复现的问题 → 降一级（逼证据落地）
- **fail-open 一律 P0**（本项目复发率最高的病，单列）
- 标准不改；但**判级可复议**（复议须书面，不改变本轮结论）

**未来警惕**：未来 milestone 可加新 P0 类别（如 M3 引入"实时性"），但**不能删除现有类别**。

- 真相 = 探针**从未跑过**，不是“127.0.0.1 也不通”

**拍板**——D-43-X 升级三规则：

1. **禁止判定型探针/门禁用 `2>/dev/null`**（含 `>/dev/null 2>&1`）
   - 失败必须响（exit != 0 且 stderr 可见）
   - 或至少把捕获到的 stderr 原文打进日志
   - 反例（2026-09-26）：wait-postgres 用 `2>/dev/null` 吞掉 IndentationError → 误判为“网络不可达”
   - 正例：`/dev/tcp/postgres/5432` 失败 → bash 退出码 125 + 错误信息可见

2. **探针必须先自证“我确实跑过”**
   - 在同一步里先 `echo probe-alive` 或写文件
   - 或干脆避开 `python -c "多行字符串"` 这种缩进/引号双重雷区
   - 优先单行 bash `/dev/tcp` 或 heredoc

3. **任何“不可达 / 不存在”的结论，必须同时附“探测动作确实执行过”的证据**，否则该结论不可引用
   - 反例（2026-09-26 run #21）：决策室 + 载曜两次报告“127.0.0.1 不通”——其实探针从未跑过
   - 正例：探针 stdout 显示 `ERROR: cannot resolve host` 或 `Connection refused` + `exit=125` = 真有执行

**影响**：
- AGENTS.md §代码审查纪律 段同步硬规则
- 后续所有判定型探针/门禁必须按此三规则

**未来警惕**：
- 不再以“探针输出 false”定 false positive——应先看探针本身是否执行过
- 调试类探针 vs 门禁类探针 区分：调试可临时静默 stderr；门禁不可
