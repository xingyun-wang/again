## 1. 一句话定位

> **我们做的产品是一个平台——老师主导的教学闭环操作系统，深度嵌入教学环节。**

v0.5 §0 定稿。e卷通 = 题库 + 报告工具；我们 = 教学闭环操作系统。

---

## 2. 产品边界硬约束

### ✅ 做透
- **教学闭环**：备课 → 出题 → 扫描 → 学情 → 反馈 → 备课下次
- **差异化作业**：4 档 + 老师审阅 + 手动调整档位
- **老师主导**：所有功能强化「老师决策」
- **纸质答题 + 扫描**：OMR 读卡机（主路径）；手机拍照 OCR 接口预留，**MVP 不做 UI**（v0.5 §6.1 强拍板）
- **老师自建题库**：**沉淀式建模**（工作流里的顺手沉淀，非「录入动作」）
- **AI 备课助手**：简化版（重点 / 难点 / 授课建议），**不出作业**

### ❌ 不做
- 自适应学习推题 / 学生端自适应 / AI 生成课件
- AI 搜索课程实录 / 课程资源链接收藏
- 校本题库
- AI 直接给学生出作业 / AI 自动批改结果作为学生最终评价

## 3. 学科与用户边界

### 3.1 MVP 起点
- **教师**：王星云本人
- **学科**：**高中地理**（不锁年级——MVP 阶段星云本人是高中地理老师；Phase 2+ 扩展）
- **班级**：单班 50 人
- **MVP 章节**：由星云每学期决定精录章节（依据 v0.5 §5.3.6 学期迭代）

### 3.2 平台最终覆盖
- 初中 / 高中 **全学段全学科**（v0.5 §8）

### 3.3 学科 / 学段边界（硬约束，v0.5 §1.4）
- **学科之间独立**：每个学科老师有独立的题库 / 学情 / 备课空间，互相看不见
- **同学科跨学段也独立**：初中地理 / 高中地理完全分开
- **核心原则**：**题库属于教师个人资产，他人无法访问**
- **未来共享题库**：教师**主动选择上传**（共建题库愿景）

### 3.4 用户扩展路径
| 阶段 | 范围 |
|---|---|
| MVP | 星云 + 自己班级（高中地理） |
| 全学段小范围 | 星云（高中地理）+ 1 初中地理老师（最小验证 = 2 人） |
| 跨学科小范围 | + 其他学科同事 |
| 单校多学科 | 单校全员老师 |
| 多校 | 多校老师 |

> **关于顺序**：全学段 in Phase 2（MVP 验证通过后立即开始）；**多学段 before 多校**（先内部矩阵验证，再规模复制）。

## 5. 题库与 AI 边界

### 5.1 题库来源（v0.5 §3.3）
| 来源 | 定位 | 状态 |
|---|---|---|
| **老师自建题库** | 教师个人资产（§3.3 原则） | ✅ MVP 核心 |
| **外部题库** | 菁优网 / 学科网 / 其他 | ✅ MVP 可用 |
| **AI 出题** | ❌ MVP 绝不碰（v0.5 §3.3 强拍板） | ⛔ 永久禁用 |
| **菁优网 API** | 战略合作伙伴保留 | ⏳ 接口预留，未来重启 |

老师角色 = **「内容策展人」**：决定每道题来源 + 本次作业的来源占比。

### 5.2 反马太效应（v0.5 §3.5）
- **D 档作业强制 20% 拔高**，从 C / B 档题池抽题
- 避免后进生自我放弃

### 5.3 AI 三类能力边界（v0.5 §5.5）
| 能力 | 性质 | MVP 状态 |
|---|---|---|
| **内容生成**（AI 出题） | AI 生成新内容 | ⛔ **永久禁用** |
| **综合分析**（AI 备课） | AI 综合学科知识库 + 学情 → 授课建议 | ✅ MVP 允许 |
| **数据提取**（AI 辅助录入） | LLM 预提取 PDF 结构化信息，星云审阅 + 编辑 | ✅ MVP 允许（人在回路） |

> **未来警惕**：AI 辅助录入如果演化为「AI 直接入库 + 老师只看」，会滑向内容生成。每次升级 AI 辅助录入前要重新评估。

### 5.4 共建题库愿景（2026-08-30 拍板）
- **MVP**：不启用 `is_public`（题库严格个人）
- **阶段 2 启动**：教师主动选择上传（共享题库）

## 7. 协作与灾难恢复

### 7.0 会话分工（最重要）

- **主聊天界面（万物） = 决策室**：方向 + 拍板 + 想法 / 建议 / 问题
- **工地 = subagent / 外派 session**：写前后端 / 跑代码 + debug

决策室上下文宝贵，避免超长拖垮主会话。所有执行类工作（写前后端 / 跑代码 / debug）在工地，决策室只做判断。

**违反警告**：长上下文调试 / 大段代码贴进决策室 = 反模式，载曜主动拦截。

**例外（不会污染决策室的改动可在决策室做）**：

决策室可直接做的改动 = 机械性 / 确定性 / 不产生大 diff / 不需要迭代测试 的小改动。典型场景：

- 1-3 行配置变更（如 .env.example 加注释、tsconfig 调字段）
- 决策记账（CHARTER / STATE.md / decisions.md / memory/ 的 append 或 timestamp 更新）
- 文档校对（typo / 链接修复 / 措辞调整）

**判断标准**：改动后能在决策室直接看到完整 diff，且 diff 行数 < 20 行，且不需要跑代码测试。

**不属于例外**：代码逻辑改动（即使 < 20 行）/ 测试改动 / 任何需要跑 pytest/mypy/ruff/build 的改动。

### 7.6 工程推进分阶段 + 每段验收（项目级硬规则，D-25 + D-36-A/B/C + D-42）

每次工程推进（M0-M7 / 任何 sub-project）必须：

1. **分阶段**：每个 phase / 阶段独立可交付
2. **每段验收**：明确的验收门槛（具体指标，可验证）
3. **通过才能进下一阶段**：任何一条不达标 = 不进
4. **工程质量贯穿**：代码的健壮性 + 可维护性 是底线，不可妥协
5. **审查材料三锚齐全**（D-36-A/B/C + D-42）：
   - **D-36-A 环境钉死**：commit SHA + 镜像 digest + PG 版本 + 依赖锁文件 hash
   - **D-36-B 证据优先级**：机器证据 > 人工转录 > 口述；人工转录是 D-36 要消灭的对象
   - **D-36-C 降级声明**：CI 跑不动时显式标「静态审查」+ 不得用于清 P0

**实施**：
- 每个 subagent 任务 brief 必须含「验收门槛」段 + 「D-36-A/B/C 三锚齐全」声明
- 验收门槛必须可验证（自动化测试 / 命令输出 / curl 等具体指标）
- 不允许「省验收」——哪怕一个 sub-phase 也要有验收门槛
- 不允许「赶进度」——跳过验收 = 工程质量崩塌
- fail-open 三层复发（代码 / 部署 / 运维）触发 §7.0 例外条款收紧：跨层复用 = 强制升级流程审查（D-42 失败模式防护三原则）

**与 §7.0 关系**：§7.0 解决「决策室 vs 工地」分工；§7.6 解决「工地内部推进节奏」+ 「审查材料硬要求」。两者都是工程质量底线。

**未来警惕**：
- 「通过才能进下一阶段」是底线，不是建议
- 任何「省验收」或「赶进度」都是反模式，载曜主动拦截
- fail-open 复发 = 不是 bug 是结构（D-42）——打地鼠式修无效，必须建三原则护栏
