## 7. 协作与灾难恢复

### 7.0 会话分工（最重要）

- **主聊天界面（万物） = 决策室**：方向 + 拍板 + 想法 / 建议 / 问题
- **工地 = subagent / 外派 session**：写前后端 / 跑代码 + debug

决策室上下文宝贵，避免超长拖垮主会话。所有执行类工作（写前后端 / 跑代码 / debug）在工地，决策室只做判断。

**违反警告**：长上下文调试 / 大段代码贴进决策室 = 反模式，载曜主动拦截。

**例外（不会污染决策室的改动可在决策室做）**：

决策室可直接做的改动 = 机械性 / 确定性 / 不产生大 diff / 不需要迭代测试 的小改动。典型场景：

- 1-3 行配置变更（如 .env.example 加注释、tsconfig 调字段）
- 决策记账（CHARTER / STATE.md / decisions.md / memory/ 的 append 或 timestamp 更新）
- 文档校对（typo / 链接修复 / 措辞调整）

**判断标准**：改动后能在决策室直接看到完整 diff，且 diff 行数 < 20 行，且不需要跑代码测试。

**不属于例外**：代码逻辑改动（即使 < 20 行）/ 测试改动 / 任何需要跑 pytest/mypy/ruff/build 的改动。

### 7.6 工程推进分阶段 + 每段验收（项目级硬规则，D-25 + D-36-A/B/C + D-42）

每次工程推进（M0-M7 / 任何 sub-project）必须：

1. **分阶段**：每个 phase / 阶段独立可交付
2. **每段验收**：明确的验收门槛（具体指标，可验证）
3. **通过才能进下一阶段**：任何一条不达标 = 不进
4. **工程质量贯穿**：代码的健壮性 + 可维护性 是底线，不可妥协
5. **审查材料三锚齐全**（D-36-A/B/C + D-42）：
   - **D-36-A 环境钉死**：commit SHA + 镜像 digest + PG 版本 + 依赖锁文件 hash
   - **D-36-B 证据优先级**：机器证据 > 人工转录 > 口述；人工转录是 D-36 要消灭的对象
   - **D-36-C 降级声明**：CI 跑不动时显式标「静态审查」+ 不得用于清 P0

**实施**：
- 每个 subagent 任务 brief 必须含「验收门槛」段 + 「D-36-A/B/C 三锚齐全」声明
- 验收门槛必须可验证（自动化测试 / 命令输出 / curl 等具体指标）
- 不允许「省验收」——哪怕一个 sub-phase 也要有验收门槛
- 不允许「赶进度」——跳过验收 = 工程质量崩塌
- fail-open 三层复发（代码 / 部署 / 运维）触发 §7.0 例外条款收紧：跨层复用 = 强制升级流程审查（D-42 失败模式防护三原则）

**与 §7.0 关系**：§7.0 解决「决策室 vs 工地」分工；§7.6 解决「工地内部推进节奏」+ 「审查材料硬要求」。两者都是工程质量底线。

**未来警惕**：
- 「通过才能进下一阶段」是底线，不是建议
- 任何「省验收」或「赶进度」都是反模式，载曜主动拦截
- fail-open 复发 = 不是 bug 是结构（D-42）——打地鼠式修无效，必须建三原则护栏
