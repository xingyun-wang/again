## 三、D-43 落字（失败模式防护第 5 条 + 第 6 条）

### 3.1 第 5 条：决策室不修代码逻辑

> **决策室不可在主会话直接 push 任何包含代码逻辑改动的 commit**。
>
> 即使改动 < 5 行、即使 diff < 20 行、即使「不需要 pytest/mypy/ruff/build」
> ——只要改动需要 push + CI 跑 build 验证，**决策室必派 subagent**。
>
> **例外范围收紧到决策记账类**（CHARTER / decisions.md / memory / STATE.md / AGENTS.md
> 的 append 或 timestamp 更新），不动代码逻辑、不动配置（除非配合 commit）。

### 3.2 第 6 条：决策室验证环路

> **事实已闭环后，决策室不可反复 exec 验证同一事实**。
>
> 单条命令 + 一次性结果 = 足够。三次以上重复验证 = 失败模式。
>
> 例外：reflog / 远端 HEAD 这类**单点可能漂移**的事实，可重 verify 一次（< 3 次）。

### 3.3 第 7 条：Deploy key 同名静默无效

> GitHub Deploy key 同名（公钥指纹一致）时新 key 静默无效，必须先 delete 才能加 Authentication Key。
>
> 用户已踩坑一次（12:35 - 14:27 期间）。下次操作前先 `git ls-remote` 看推送结果，
> 不只看 `ssh -T` 认证返回。
